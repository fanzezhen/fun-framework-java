# 补充提示词文档

向提示词/规范文档补充内容。读者是 Agent 不是人，一切以简洁可执行为先。

## 参数

- `$1` 文档路径（相对或绝对）
- `$2` 需补充的内容（可为粗略描述，由你压缩成规范表述）

参数缺失时向用户追问，不臆测。

## 步骤

1. 探查目标文档所在项目是否有提示词/规范约定（同目录或上层的 index、全局/总纲类文档）；有则读取，作为风格与归属权威；没有则用下方内置规范
2. 读 `$1` 目标文档；不存在则视为新建
3. 判定归属：`$2` 是否属于 `$1` 的维度。若更适合其他文件，提示用户并给出建议落点，不硬塞
4. 把 `$2` 压缩为 Agent 表述（见下），与目标文档已有内容去重、合并
5. 就地重整目标文档：按原有结构/标题组织，不只在末尾追加
6. 新建文档时：若项目存在索引/清单类文档，登记一行

## Agent 表述规范

- 简洁第一：能删的字都删，一句话说清不写两句
- 列表代替层级，短句代替段落
- 写"做什么"，不写"为什么"（除非约束需要理由才能正确执行）
- emoji / 加粗 / 引用块 / 表格：帮 Agent 理解或执行才加，纯装饰一律不加
- 中文；专业名词可留英文，首次附中文注释
- 不硬编码版本号，用"最新稳定版""查看构建文件获取版本"等表述
- 同一规则只在一处写，专属规则下沉到归属文件，避免跨文件重复与冲突

## 可插拔约束

各提示词文件可被单独抽出带到其他项目，须能独立正确执行。关键区分"依赖"与"联动"：

- 禁止读依赖：不得要求"读某兄弟文件 / 见某兄弟文件 / 规则以某兄弟文件为准"作为执行前提。唯一例外是项目全局/总纲类文档
- 允许联动写：可要求"某变化时同步更新某文件"（如同步 `java脚手架.md`）；目标文件不存在则跳过而非失效
- 通用文档不写死具体项目的路径/模块名/文件名，用角色化表述（如"模块组根""构建文件""索引文档"）

## 完成前自查

- [ ] 内容落在正确文件（归属无误）
- [ ] 已与原内容去重、按原结构重整
- [ ] 表述简洁、无冗余解释、无硬编码版本号
- [ ] 无对兄弟文件的读依赖（联动写允许）、无写死的项目专属路径
- [ ] 新文档已登记到项目索引/清单（若有）
