## 维护原则

本目录文档面向 Agent，标准是能看懂能执行：列表代替层级，短句代替段落，写"做什么"不写"为什么"，emoji/加粗/引用块仅必要时用。

## 文档划分

按"作用域 / 语言 / 端 / 能力"分文件，便于按项目类型插拔。各文件只放本维度专属内容，专属规则按归属轴下沉，避免跨文件重复与冲突。

- `提示词/全局提示词.md`：全局通用规范，所有项目读（本文件）
- `提示词/本项目.md`：仅开发本框架（fun-framework-java）时读，用本框架的子项目不读
- `专业提示词/测试.md`：通用测试理念，语言/端无关，所有项目涉及测试时必读
- `专业提示词/java.md`：Java 通用规则（依赖 `java脚手架.md`、`后端.md`、`测试.md`）
- `专业提示词/java-springboot.md`：SpringBoot 专属增量（依赖 `java.md`）
- `专业提示词/前端.md`：前端专属（依赖 `测试.md`）
- `专业提示词/后端.md`：后端通用（API 设计、分层命名，语言无关）
- `专业提示词/linux.md`：Linux 运维专属
- `专业提示词/java脚手架.md`：java项目的框架能力索引，涉及Java改动必读

插拔规则：按项目类型带走对应文件 + 其声明的依赖。

## 沟通

- 回复、文档、代码注释统一中文，专业名词可保留英文（首次附中文注释）
- 代码注释只写长期意图、约束、边界，不写思考/调试/任务过程

## 基础职责

- 改代码前先了解上下文
- 新增类/方法加 `@since 版本号`；非借鉴代码不加 `@author`
- 维护 TODO 与关键文档准确性
- 输出含"任务完成"关键词，结尾附当前时间（YYYY-MM-DD HH:mm:ss）
- 改动项目目录外文件须在结尾明确提醒

## 输入 "continue"

1. 定位文档（缺失则建占位）：`doc/dev/提示词/` 下 RECOVERY_PLAN.md（风险）、OVERVIEW.md（架构约束）、TODO.md（分阶段任务）、CHECKLIST.md（开关/脚本）
2. 取 TODO.md 第一个未完成项；全完成则输出"所有任务已完成"并结束
3. 拆 3~5 子步骤，最小改动执行
4. 勾选 TODO，必要时更新 OVERVIEW/CHECKLIST/RECOVERY_PLAN
5. 输出：标题、关键修改 ≤3 条、后续提醒、结尾"任务完成"

## 质量

- 向后兼容；任务含糊先在文档澄清再做
- 无法验证时标注"未验证"原因
- 单文件 ≤1000 行，单方法 ≤80 行
- 优先复用现有代码；边界情况融入常规逻辑，不打补丁；不留无用代码

## 脚手架查询

涉及通用功能（统一返回、分页、缓存、认证等）前先读 `专业提示词/java脚手架.md`（本地 → GitHub Raw → Gitee Raw）；框架已有禁止重复实现，不确定问用户。

脚手架新增/变更（新模块、API 变更、用法变化）须同步更新 `java脚手架.md`；内部优化、测试、格式、用法不变的版本升级不触发。

## 代码格式（Java）

- 4 空格缩进、UTF-8、LF、文件末尾空行；单行 ≤120 字符（建议）/ ≤150（硬限）
- 二元运算符（`|| && +` 等）换行放行尾
- 一旦换行，每个参数/条件独立一行，不允许部分合并
- 枚举常量末尾留逗号，分号独立成行：

```java
public enum StatusEnum {
    ACTIVE(1, "激活"),
    INACTIVE(0, "未激活"),
    ;
}
```

## 测试

- 新功能：写测试 → 跑红 → 实现 → 跑绿 → 重构
- 修 Bug：写复现测试 → 跑红 → 改 → 跑绿 → 回归
- 变更须通过 lint/format/test 才提交；新增/变更功能补单测+集测
- 数据库测试优先 H2 内存库；用户未要求不引入新测试框架；缺测试要求时在根 `AGENTS.md` 补齐
- 复杂任务（多模块/跨域）：建 `.agentdocs/workflow/YYMMDD-任务简述.md`，拆阶段（目标/验证/风险），TodoWrite 跟踪，每阶段完成即跑测试

### SpringBoot 启动限制

- 禁止：后台/`nohup`/`&` 启动 SpringBoot 或任何长期 Web 服务
- 允许：`mvn test/verify/package`、`@SpringBootTest`、配置/依赖检查
- 服务由开发人员手动启，Agent 只做实现、测试、静态验证

### 进程与长任务

- 启容器的测试（mockMvc、`@SpringBootTest`）跑完查残留：`tasklist | findstr <名>`，有则 `taskkill /PID <pid> /F`
- 长任务（mvn 编译/测试/打包）不被动等，定时看日志；卡固定阶段或日志长时间无新增即视为异常，定位卡点后中止或调整

## 安全

- 避免 SQL 注入、XSS、命令注入等 OWASP Top 10
- 不提交 `.env`、`credentials.json` 等敏感文件

## 文档与记忆

- 所有 AI 文档放 `.agentdocs/` 子目录，Markdown；禁止在项目根建临时文件，须放 `.gitignore` 声明的非提交目录
- `.agentdocs/index.md` 为根索引，记录各文档内容与读取场景；新增文档须登记
- 任务文档：`.agentdocs/workflow/YYMMDD-任务简述.md`
- 不建工作汇报/任务总结；优先更新现有内容，更新时按原格式重整不只追加末尾
- 发现跨模块约束/历史决策缺失，整理补齐视为任务一部分

### Skills / MCP

- Skills：`.claude/skills/`；MCP：`.mcp.json`

## 任务处理

- 启动新任务先读 `.agentdocs/index.md`
- 简单任务直接改；复杂任务（多模块/跨域）先做 plan
- 需求不明确先澄清；简单问题超两次未解决视为复杂任务
- 对用户设想客观分析，不一味遵循

## 任务回顾

- 完成后呈现最终消息前回顾：产出新可复用模式/跨文件约束/关键决策 → 写入对应文档；仅局部影响 → 不写回
- 复杂任务：每阶段更新任务文档 TODO；全完成提醒用户验收，确认后移至 `.agentdocs/workflow/done/` 并从 `index.md` 移除

## 任务完成输出 commit message

- 基于 `git status`/`git diff` 汇总未提交改动，输出建议 commit message（仅建议，不执行 add/commit/push）
- 标题：Conventional Commits 前缀（feat/fix/refactor/docs/test/chore）+ 可选作用域 + 中文简述，≤72 字符
- 多类改动在标题下空行后用中文条目列出

## 故障处理

- 缺依赖/测试失败/权限受限：记录具体错误 → 给可行建议或所需人工操作 → 返回"部分完成"并解释，不沉默失败

## 服务对象与原则

资深首席架构师（30 年+）。核心偏好：

1. Good Taste：消除边界情况，特殊变正常
2. Never break userspace：向后兼容优先
3. 实用主义：解决实际问题
4. 简洁：超 3 层缩进就重构，函数只做一件事

## 三层穿梭思维

现象层接收症状 → 本质层定位根因 → 哲学层提炼原则 → 现象层输出方案。

典型映射：NPE→防御缺失→"信任但验证"；死锁→资源竞争→"共享即纠缠"；内存泄漏→生命周期混乱→"所有权即责任"；性能瓶颈→复杂度失控→"时空权衡"。
