## 🔗 框架能力查询

在编写代码时请注意:

### 必须先查阅 `后端脚手架.md` 的场景


- ✅ 需要**统一返回格式**(⚠️ 框架已自动封装,Controller 直接返回业务对象)
- ✅ 需要**分页查询**(PageModel、IPage 使用)
- ✅ 需要**全局异常处理**(ServiceException 抛出,⚠️ 框架自动处理)
- ✅ 需要**请求参数校验**(Validation 注解)
- ✅ 需要**对象转换**(Entity ↔ BO ↔ VO)
- ✅ 需要**数据库操作**(MyBatis-Plus BaseMapper/IService)
- ✅ 需要配置**全局异常处理器**(GlobalExceptionHandler)
- ✅ 需要配置**跨域、拦截器、过滤器**等 Web 层组件
- ✅ 需要集成**Redis、Elasticsearch、Sa-Token、Sentinel**等第三方组件
- ✅ 需要配置**MyBatis-Plus**(分页插件、逻辑删除、自动填充等)
- ✅ 需要配置**接口文档**(SpringDoc/Swagger)
- ✅ 需要**配置文件加密**(Jasypt)

### 无需查阅的场景

- ❌ 定义业务 Controller、Service、Mapper
- ❌ 编写 Spring Boot 启动类或配置类(非框架集成相关)

## 📝 文档版本号管理原则

**禁止在文档中硬编码版本号**，适用于所有文档类型（README、提示词、注释等）：

### 规则说明

- ❌ **禁止**: "基于 Spring Boot 4.0.5"、"MyBatis Plus 3.5.16"、"Java 21"、"v5.0.0"
- ✅ **正确**: "基于 Spring Boot 最新稳定版本"、"查看 pom.xml 获取当前版本"
- **原因**: 作为持续迭代的开源项目，依赖版本频繁更新，硬编码版本号会导致文档过时且维护成本高
- **例外**: 仅在 git commit message 和 pom.xml 中记录具体版本号

### 禁止场景

- ❌ README.md 及各模块 README
- ❌ 提示词文档（全局提示词、专业提示词）
- ❌ 代码注释（描述框架版本时）
- ❌ CLAUDE.md 项目指导文档

### 允许场景

- ✅ `pom.xml` 中的依赖版本声明
- ✅ git commit message (如 "chore: 升级 Spring Boot 到 4.1.0")
- ✅ CHANGELOG.md（如果创建）

### 推荐表达

| 场景 | 推荐表达 |
|------|---------|
| 技术栈说明 | "基于 Spring Boot、Java、MyBatis Plus 最新稳定版本" |
| 版本查询 | "查看 pom.xml 获取当前依赖版本" |
| 依赖管理 | "依赖版本由框架父 POM 统一管理" |
| 更新说明 | "持续追踪并升级到最新稳定版本" |

### 实施方法

1. **编写文档时**: 使用"最新稳定版本"等通用表达
2. **更新文档时**: 检查并移除硬编码版本号
3. **版本信息来源**: pom.xml 作为唯一权威来源
4. **AI Agent 行为**: 自动应用此规则，遇到版本号相关描述时主动使用通用表达

## 🔄 开源项目迭代原则

### 技术栈管理

- **持续更新**: 定期升级依赖到最新稳定版本
- **统一管理**: 所有版本号在父 POM 中统一声明
- **禁止覆盖**: 子模块禁止覆盖父 POM 定义的版本号
- **文档同步**: 版本升级后无需更新文档（因为文档中没有硬编码版本号）

### 版本查询方式

```bash
# 查看当前项目使用的 Spring Boot 版本
Read pom.xml | grep spring-boot

# 查看所有依赖版本
Read pom.xml 查看 <properties> 节点
```
