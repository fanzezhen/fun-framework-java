# 测试规范（通用）

所有项目通用，与语言/端无关。专属用法见对应文档：Java → `java.md`；SpringBoot（H2、`@SpringBootTest`、MockMvc）→ `java-springboot.md`；前端 → `前端.md`。

## TDD

- 新功能：写测试 → 跑红 → 实现 → 跑绿 → 重构
- Bug：写复现测试 → 跑红 → 修代码 → 跑绿 → 全量回归

## 命名

- 格式：`方法_场景_预期`，配合描述性标注（如 `@DisplayName` / `it("...")`）
- 示例：`registerUser_UsernameExists_ShouldThrow`
- 禁：`test1`、`testXxx` 等模糊命名

## 结构

Given-When-Then：准备数据 → 执行操作 → 验证结果。

## 覆盖范围

每个方法至少覆盖：正常场景、边界条件、异常场景。

## Mock 约束

- 优先真实协作对象，少用 mock，让测试贴近真实行为
- 仅在隔离外部不可控依赖（第三方 API、消息中间件等）时 mock，并在测试中注明原因

## 断言

一个测试聚合多个相关校验一次性执行（任一失败仍报告其余），避免首个失败掩盖后续问题。

## 测试数据工厂

重复构造的测试对象抽到工厂方法/构造器，避免每个用例重复样板代码。

## 覆盖率

不设分层百分比指标。原则：凡能用测试覆盖的逻辑尽量全覆盖——每个可测方法补正常/边界/异常场景，不为凑数字留空白，也不因数字达标而停手。

## 反模式（禁止）

- 依赖外部环境（真实 DB / 外部 API）
- 测试间有依赖（共享可变状态）
- 不清理数据（用例间状态残留）

## 完成前自查

- [ ] 测试全通过
- [ ] 可覆盖逻辑已尽量全覆盖
- [ ] 命名清晰、有描述性标注
- [ ] Given-When-Then 结构
- [ ] 覆盖正常/边界/异常
- [ ] 测试相互独立、数据自动清理、无外部依赖
