# fun-framework-java 脚手架能力索引

**用途**: 编写新代码涉及通用功能时查阅，避免重复实现框架已有能力。

**仓库**: GitHub/Gitee `fanzezhen/fun-framework-java`  
**版本管理**: 持续追踪最新稳定版本，查看 pom.xml 获取当前依赖版本  
**开发流程**: 查本文档 → 找模块 → 读 README → 看测试 → 写代码

**核心原则**:
1. 先查后写
2. 依赖版本由框架父 POM 统一管理，禁止覆盖
3. 不确定时查文档或询问用户
4. **分层解耦**: Service 层禁止依赖 MyBatis-Plus 的 `Page`/`IPage`，DAO 层使用框架模型 (`PageCondition`/`PageDTO`) 作为方法签名

## 框架模块总览

### 1. 核心基础模块 (fun-framework-core)

#### 1.1 核心模型 (fun-framework-core-model)
**功能**: 通用数据模型和工具  
**文档**: [README.md](https://github.com/fanzezhen/fun-framework-java/blob/master/fun-framework-core/fun-framework-core-model/README.md) ([Gitee](https://gitee.com/fanzezhen/fun-framework-java/blob/master/fun-framework-core/fun-framework-core-model/README.md))

**核心内容**:
- `Result<T>`: 统一返回结果 (code/message/data)
- `PageDTO<T>`: 分页查询结果模型 (Service → Controller, 支持 `convert()` 方法转换)
- `MapperFacadeUtil`: 对象映射工具 (基于 Orika)
- `StrTemplateUtil`: 字符串模板工具 (支持 `${var}` 和 `$var` 格式)
- `BaseBO<P>/BaseDTO<P>`: 业务对象基类 (包含 id/createTime/createUserId，类型为 P)
- `BaseTenantBO<P>/BaseTenantDTO<P>`: 多租户业务对象基类 (额外包含 tenantId，类型为 P)
- `IGenericEntity<P>`: 非 MyBatis Entity 接口
- **分页请求模型**: `PageRequest` (Controller 层接收分页参数)
- **分页查询条件**: `PageCondition` (Service/Dao 层传递分页条件)
- **🔥 分页转换工具**: `PageUtil` (DAO 层 IPage ↔ PageDTO 转换，PageCondition → Page 转换)

**继承规范**:
- BO → 继承 `BaseBO<P>` (Service 层返回，P 为主键类型)
- DTO → 继承 `BaseDTO<P>` (Controller 层入参/出参，P 为主键类型)
- 多租户 → 使用 `BaseTenantBO<P>/BaseTenantDTO<P>` (tenantId 类型与主键 P 一致)
- 非 MyBatis Entity → 实现 `IGenericEntity<P>`

**注意**: 多租户 Base 类的 `tenantId` 字段类型为泛型 `P`，与主键类型保持一致

**常用方法**:
- `MapperFacadeUtil.map(source, TargetClass)` - 对象映射
- `MapperFacadeUtil.page(pageDTO, SourceClass, TargetClass)` - 分页对象映射
- `PageUtil.toPageResult(IPage)` - IPage → PageDTO (DAO 层使用)
- `PageUtil.toPage(PageCondition)` - PageCondition → Page (DAO 层使用)
- `PageDTO.convert(Function)` - 自定义分页数据转换

**注意**: 
- Controller 返回值自动封装为 `Result<T>`, 无需手动调用 `Result.success()`
- Spring Boot 项目需添加 `fun-framework-core-springboot` 依赖
- **重要**: BO/DTO 的 `tenantId` 类型为泛型 `P`，与主键类型一致；MyBatis Entity 的 `tenantId` 类型根据主键策略固定 (Integer/Long/String)

#### 🔥 分层对象模型使用规范

**重要**: 所有分层对象必须使用或继承框架提供的 `com.github.fanzezhen.fun.framework.core.model` 下的基础类，禁止手动定义重复字段。

##### 1. 分页查询场景

**核心原则**: DAO 层使用框架模型 (`PageCondition` / `PageDTO`)，避免 MyBatis-Plus 模型 (`Page` / `IPage`) 侵入 Service 层

| 层次 | 入参类型 | 返回类型 | 说明 |
|------|---------|---------|------|
| **Controller 层** | `PageRequest` 或其子类 | `PageDTO<DTO>` | 接收前端分页参数，返回分页结果 |
| **Service 层** | `PageRequest` 或 `PageCondition` 子类 | `PageDTO<DTO>` | 接收分页请求，返回分页 DTO |
| **DAO 层** | `PageCondition` 或其子类 | `PageDTO<Entity>` | 🔥 入参/返回值均使用框架模型，而非 MyBatis 模型 |

**分层解耦要求**:
1. DAO 层方法签名: `PageDTO<Entity> page(PageCondition condition)`
2. DAO 内部使用 `PageUtil.toPage(condition)` 转换为 MyBatis 的 `Page`
3. DAO 内部使用 `PageUtil.toPageResult(iPage)` 转换为框架的 `PageDTO`
4. Service 层完全不使用 MyBatis-Plus 的 `Page`/`IPage` 类

**标准实现模式**:
```java
// DAO 层标准写法
default PageDTO<Entity> page(XxxPageCondition condition) {
    LambdaQueryWrapper<Entity> wrapper = buildWrapper(condition);
    return PageUtil.toPageResult(selectPage(PageUtil.toPage(condition), wrapper));
}

// Service 层标准写法
public PageDTO<DTO> page(XxxPageRequest request) {
    XxxPageCondition condition = convertToCondition(request);
    PageDTO<Entity> entityPage = mapper.page(condition);
    return MapperFacadeUtil.page(entityPage, Entity.class, DTO.class);
}
```

##### 2. Service 层返回值规范

**核心原则**: Service 层禁止直接返回 Entity，必须返回 DTO 或 BO

| 返回类型 | 使用场景 |
|---------|---------|
| **DTO** (推荐) | Service → Controller，直接返回给前端 |
| **BO** | Service 内部流转，需进一步处理 |
| **PageDTO<DTO>** | 分页查询结果 |
| **List<DTO>** | 列表查询结果 |

**转换方法**: 使用 `MapperFacadeUtil.map(entity, DTO.class)` 将 Entity 转换为 DTO

##### 3. 业务对象继承规范

| 对象类型 | 继承基类 | 使用层次 | 包含字段 |
|---------|---------|---------|---------|
| **DTO** (推荐) | `BaseDTO<P>` | Controller 入参/出参，Service 返回值 | id, createTime, createUserId |
| **BO** | `BaseBO<P>` | Service 内部流转 | id, createTime, createUserId |
| **多租户 DTO** | `BaseTenantDTO<P>` | 多租户场景 | 上述 + tenantId |
| **多租户 BO** | `BaseTenantBO<P>` | 多租户场景 | 上述 + tenantId |

**注意**: 泛型 `P` 为主键类型，禁止手动定义 id/createTime/createUserId/tenantId 字段

##### 4. 禁止事项检查清单

- [ ] ❌ Controller 手动定义分页参数 (`@RequestParam Integer current`) → 使用 `PageRequest`
- [ ] ❌ DAO 层入参/返回使用 `Page`/`IPage` → 使用 `PageCondition`/`PageDTO`
- [ ] ❌ Service 依赖 MyBatis-Plus 的 `Page`/`IPage` → DAO 层封装转换
- [ ] ❌ BO/DTO 手动定义基础字段 (id/createTime 等) → 继承 `BaseDTO<P>`/`BaseBO<P>`
- [ ] ❌ Service 层直接返回 Entity → 使用 `MapperFacadeUtil.map()` 转换为 DTO
- [ ] ❌ Controller 手动封装 `Result.success()` → 直接返回 DTO，框架自动封装

##### 5. 编写代码前检查清单

- [ ] Controller 接收分页参数使用 `PageRequest` 子类
- [ ] Service 返回值使用 DTO (禁止返回 Entity)
- [ ] DAO 层使用 `PageCondition` 入参，`PageDTO<Entity>` 返回值
- [ ] DAO 内部使用 `PageUtil.toPage()` 和 `PageUtil.toPageResult()` 转换
- [ ] DTO/BO 继承对应的 Base 类 (`BaseDTO<P>` / `BaseBO<P>`)
- [ ] 没有手动定义 id/createTime/createUserId/tenantId 字段
- [ ] 泛型 P 与 Entity 主键类型一致

#### 1.4 线程组件 (fun-framework-core-thread)
**功能**: 线程池管理和异步任务  
**文档**: [README.md](https://github.com/fanzezhen/fun-framework-java/blob/master/fun-framework-core/fun-framework-core-thread/README.md) ([Gitee](https://gitee.com/fanzezhen/fun-framework-java/blob/master/fun-framework-core/fun-framework-core-thread/README.md))

**核心内容**: 
- `ThreadPoolExecutorRepository`: 管理 `java.util.concurrent.ThreadPoolExecutor`
- `ThreadPoolTaskExecutorRepository`: 管理 Spring `ThreadPoolTaskExecutor`（位于 `fun-framework-core-springboot` 模块）
- `ExecutorHolder`: 异步任务执行器，支持批量任务执行和结果收集
- `ThreadPoolTaskDecorator`: 线程池装饰器，自动传递上下文（如 traceId、用户信息等）到子线程

**场景**: 异步任务、并发任务、线程池统一管理、父子线程上下文传递

**使用示例**:
```java
// 创建线程池（Spring Boot 环境）
import com.github.fanzezhen.fun.framework.core.springboot.thread.ThreadPoolTaskExecutorRepository;
ThreadPoolTaskExecutor executor = ThreadPoolTaskExecutorRepository.newThreadPoolTaskExecutor("myPool", 5, 10);

// 创建线程池（非 Spring 环境）
import com.github.fanzezhen.fun.framework.core.thread.ThreadPoolExecutorRepository;
ThreadPoolExecutor executor = ThreadPoolExecutorRepository.newThreadPoolExecutor("myPool", 5, 10);

// 异步执行任务
executor.execute(() -> {
    // 子线程自动继承父线程的上下文
    Long userId = ContextHolder.getUserId();
});
```

**注意**: 
- 旧代码中的 `PoolExecutors` 类已废弃，请使用 `ThreadPoolExecutorRepository` 或 `ThreadPoolTaskExecutorRepository`
- 使用 `ThreadPoolTaskExecutorRepository` 创建的线程池会自动配置上下文传递

#### 1.5 上下文组件 (fun-framework-core-context)
**功能**: 全局上下文管理  
**文档**: [README.md](https://github.com/fanzezhen/fun-framework-java/blob/master/fun-framework-core/fun-framework-core-context/README.md) ([Gitee](https://gitee.com/fanzezhen/fun-framework-java/blob/master/fun-framework-core/fun-framework-core-context/README.md))

**核心内容**: 
- `ContextHolder`: 基于 `TransmittableThreadLocal` 的上下文管理，支持父子线程间的上下文传递
- `FunContextFilter`: Web 过滤器，自动提取请求头数据放入上下文
- `@ContextHeader`: 注解 + AOP 实现上下文校验

**场景**: 获取当前登录用户、多租户数据隔离、跨层传递上下文、异步任务中访问上下文

**使用示例**:
```java
// 获取上下文信息
Long userId = ContextHolder.getUserId();
Long tenantId = ContextHolder.getTenantId();
String traceId = ContextHolder.getTraceId();

// 异步任务中自动继承上下文（需配合 ThreadPoolTaskExecutorRepository）
executor.execute(() -> {
    Long userId = ContextHolder.getUserId(); // 可以获取到父线程的 userId
});
```

**注意**: 
- v2.x 版本升级为 `TransmittableThreadLocal`，支持线程池场景下的上下文传递
- 需引入 `com.alibaba:transmittable-thread-local` 依赖

- 自动填充创建时间/更新时间
- 逻辑删除

**MyBatis-Plus Entity 继承规范**:

MyBatis-Plus 实体类必须继承 `com.github.fanzezhen.fun.framework.mp.base.entity` 下的 BaseEntity,根据主键策略选择:

| 主键策略 | 路径 | 主键类型 | 说明 |
|---------|------|---------|------|
| 自增 | `increment.BaseEntity` | `Integer` | 单体应用推荐 |
| UUID | `uuid.BaseEntity` | `String` | 分布式系统 |
| 雪花算法 | `snowflake.BaseEntity` | `Long` | 高并发分布式推荐 |
| 多租户 | `*.tenant.BaseTenantEntity` | 根据策略 | 额外包含 tenantId |
| 自定义主键类型 | `*.BaseGenericEntity<P>` | 泛型 `P` | 需要自定义主键类型时使用 |

BaseEntity 提供的字段(自动填充):
- `id`: 主键 (类型根据策略不同: Integer/String/Long)
- `createTime`: 创建时间 (INSERT 自动填充)
- `createUserId`: 创建人ID (INSERT 自动填充，类型与 id 一致)
- `tenantId`: 租户ID (仅多租户 BaseEntity，类型与 id 一致)

示例:
```java
// 自增主键
import com.github.fanzezhen.fun.framework.mp.base.entity.increment.BaseEntity;
@TableName("sys_user")
public class UserEntity extends BaseEntity {
    private String username;
}

// 多租户 + 雪花算法
import com.github.fanzezhen.fun.framework.mp.base.entity.snowflake.tenant.BaseTenantEntity;
@TableName("tenant_order")
public class OrderEntity extends BaseTenantEntity {
    private String orderNo;
}
```

## 常见错误速查

| 错误 | 正确做法 |
|------|---------|
| Controller 手动调用 `Result.success()` | 直接返回 DTO，框架自动封装 |
| Service 直接返回 Entity | 使用 `MapperFacadeUtil.map()` 转为 DTO |
| Service 使用 `IPage`/`Page` | DAO 返回 `PageDTO`，Service 不依赖 MyBatis |
| DAO 返回 `IPage<Entity>` | 使用 `PageUtil.toPageResult()` 转为 `PageDTO<Entity>` |
| 手动定义 id/createTime 字段 | 继承 `BaseDTO<P>`/`BaseBO<P>`/`BaseEntity` |
| 覆盖框架依赖版本 | 继承框架父 POM，不覆盖版本 |
| 手动编写对象映射 | 使用 `MapperFacadeUtil.map()/page()` |
| try-catch 手动处理异常 | 抛出 `ServiceException`，框架统一处理 |

## 使用建议

**何时查阅**: 实现通用功能、集成第三方服务、不确定框架是否已提供能力时查阅

**查阅流程**: 快速查询表 → 找模块 → 读 README → 写代码

**Base 类选择**:
- Entity: `increment.BaseEntity` (单体) / `snowflake.BaseEntity` (分布式) / `*.tenant.BaseTenantEntity` (多租户)
- DTO: `BaseDTO<P>` (Service 返回值、Controller 层) / `BaseTenantDTO<P>` (多租户)
- BO: `BaseBO<P>` (Service 内部) / `BaseTenantBO<P>` (多租户)

**🚨 必查项**:
1. Service 返回值必须是 DTO/BO，禁止返回 Entity
2. DAO 层使用 `PageCondition` 入参、`PageDTO<Entity>` 返回，通过 `PageUtil` 转换
3. Service 层禁止依赖 MyBatis-Plus 的 `Page`/`IPage`
4. DTO/BO 必须继承对应 Base 类，禁止手动定义基础字段
